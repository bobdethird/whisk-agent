# SO-101 MuJoCo Simulation

This repo contains the MuJoCo setup for the ECE 4560 SO-101 assignment. The current workflows cover:

1. Generated SO-101 table scenes with multiple `tag36h11` AprilTags.
2. Camera rendering and AprilTag pose estimation from named MuJoCo cameras.
3. Starting-pose, assignment-motion, and Cartesian IK demos.
4. A vision agent that optionally randomizes table-tag positions and moves above every detected tag.
5. A focused cup-pickup scene that detects a cup-mounted AprilTag and tries to lift the cup.

## Requirements

- macOS, Linux, or Windows with a working graphical desktop
- Conda or Miniforge
- Python environment named `whisk-agent`

On macOS, use `mjpython` for scripts that open the MuJoCo viewer. MuJoCo installs this command with the Python package.

## Fresh Setup

From the repo root:

```bash
cd /path/to/agent-1
```

Create the conda environment if it does not already exist:


Activate it:

Install the Python dependencies:


Verify the simulator and kinematics packages import:

```bash
python -c "import mujoco, lerobot, placo; print(mujoco.__version__)"
```

## Model Files

The expected model layout is:

```text
simulation_code/
└── model/
    ├── apriltag_world_metadata.json
    ├── scene.xml
    ├── scene_cup.xml
    ├── so101.xml
    ├── so101_new_calib.xml
    ├── so101_new_calib.urdf
    ├── robotstudio_so101/
    └── assets/
        ├── apriltags/
        │   ├── tag_card.obj
        │   ├── tag36h11-<id>.svg
        │   └── tag36_11_<id>.png
        └── *.stl
```

The active MuJoCo robot model is `simulation_code/model/so101.xml`, vendored from the Google DeepMind MuJoCo Menagerie SO-101 model. The `robotstudio_so101/` directory keeps the upstream README, license, sample scenes, and assets for provenance.

If the SO-101 model files are missing, download the Menagerie SO-101 package from:

https://github.com/google-deepmind/mujoco_menagerie/tree/main/robotstudio_so101

Place `so101.xml` and the package assets in `simulation_code/model/`, and keep the upstream package copy under `simulation_code/model/robotstudio_so101/`.

`scene.xml` is generated by `mujoco_sim/generate_apriltag_world.py`. Keep robot geometry in `so101.xml`, and change world objects such as table tags, cameras, floor, or lighting through `mujoco_sim/apriltag_world_config.py`. `scene_cup.xml` is a separate focused cup-pickup scene with a freejoint cup and a cup-mounted AprilTag.

## Generate The AprilTag World

The generated table world contains six `tag36h11` AprilTags, IDs `0` through `5`, placed as thin textured squares on the work table. The SVG files in `simulation_code/model/assets/apriltags/` are the source assets. The generator rasterizes each full SVG, including the white quiet zone needed for detection, and scales each card so the black AprilTag square is the configured detector `tag_size` in meters.

Regenerate `simulation_code/model/scene.xml` and `simulation_code/model/apriltag_world_metadata.json`:

```bash
conda activate whisk-agent
cd /path/to/agent-1
python mujoco_sim/generate_apriltag_world.py
```

Use SVGs named `tag36h11-<id>.svg` for source tags. The generated PNG texture uses the MuJoCo-friendly name `tag36_11_<id>.png`, for example `tag36_11_00000.png`. The generic `tag_card.obj` mesh supplies stable UV coordinates; it is reused for every tag, while each tag gets its own texture. The cup-pickup scene also uses `tag36_11_00006.png` for the cup-mounted tag ID `6`.

## Forward And Inverse Kinematics

The kinematics layer uses LeRobot's Placo-backed `RobotKinematics` with the local URDF at `simulation_code/model/so101_new_calib.urdf` and the target frame `gripper_frame_link`.

The local adapter in `so101_kinematics.py` keeps the same joint dictionary convention used by the MuJoCo helpers:

- Arm joints are in degrees.
- `gripper` is preserved as a `0..100` command value.
- FK/IK poses default to MuJoCo Menagerie's `gripperframe` site convention.

LeRobot's URDF frame and MuJoCo Menagerie's `gripperframe` site differ by a fixed rotation and a small translation. The adapter applies both corrections so validation and IK targets line up with the simulation.

High-level `move(...)` commands target the visible claw/pinch point rather than the internal `gripperframe` site. The motion layer applies the Menagerie fingertip offset and then refines IK with the wrist roll locked at the standard `-90°` camera-on-top orientation.

Validate LeRobot/Placo FK against MuJoCo:

```bash
conda activate whisk-agent
cd /path/to/agent-1
python mujoco_sim/validate_kinematics.py
```

Expected errors should be very small, around a few microns of position error and about `1e-5` radians of rotation error.

Run the Cartesian IK demo:

```bash
conda activate whisk-agent
cd /path/to/agent-1
mjpython mujoco_sim/run_cartesian_ik_demo.py
```

The demo starts from the standard pose, samples a random nearby end-effector target, solves it using IK, moves there, and then returns to the starting pose.

The `motion.move(...)` helper moves to absolute world-space coordinates in meters and can also command a final gripper opening:

```python
move(env, (0.08, 0.06, 0.05), gripper_position=50.0)
```

In that example, the target point is `x=8 cm`, `y=6 cm`, `z=5 cm` in the MuJoCo/world coordinate frame, not an offset from the starting gripper pose.

`main.py` runs the AprilTag-following agent. By default it randomizes the six table-tag positions at runtime, estimates tag poses from rendered camera images, opens the gripper, and moves to a hover point above each detected tag:

```bash
conda activate whisk-agent
cd /path/to/agent-1
mjpython main.py --seed 1 --camera table_observer
```

Use fixed generated tag positions instead of randomizing:

```bash
mjpython main.py --fixed-tags --camera table_observer
```

Useful randomization controls:

- `--seed` makes random tag placement reproducible.
- `--tag-x-range MIN MAX` and `--tag-y-range MIN MAX` bound the randomized XY placement area.
- `--tag-min-spacing` prevents randomized tags from overlapping too closely.
- `--hover-height` controls the world `+Z` offset above each detected tag. The default is `0.02` m.

The shared detector in `pose_estimation.py` can search multiple cameras, group detections by per-ID tag sizes, and skip missing camera names. `main.py` uses the configured table cameras; `run_cup_pickup.py` narrows detection to the cup tag and searches `table_observer` before `cup_observer`.

In the viewer, a green sphere marks the hover point estimated from vision, and a red sphere marks the equivalent hover point from the MuJoCo ground-truth tag site so you can compare estimate versus simulation truth. The default vision render is 2560 x 1920.

## Run The Cup Pickup Test

`mujoco_sim/run_cup_pickup.py` loads `simulation_code/model/scene_cup.xml`, configures cup mass/friction/size, detects the cup-mounted AprilTag ID `6`, converts that tag pose to a green cup-center point, then moves through approach, pregrasp, close, squeeze, and lift stages. A blue marker shows the low pregrasp waypoint. The result prints pass/fail, cup height, and contact diagnostics.

Run the visual pickup test:

```bash
conda activate whisk-agent
cd /path/to/agent-1
mjpython mujoco_sim/run_cup_pickup.py
```

Run without opening the viewer:

```bash
python mujoco_sim/run_cup_pickup.py --headless
```

Run the built-in parameter sweep over jaw friction, cup mass, and gripper force:

```bash
python mujoco_sim/run_cup_pickup.py --sweep
```

Important pickup controls:

- `--cup-position X Y Z` changes the configured cup pose before detection.
- `--cup-radius`, `--cup-mass`, `--cup-friction`, `--jaw-friction`, and `--gripper-force` tune contact behavior.
- `--first-waypoint-forward-offset` and `--first-waypoint-left-offset` tune the pregrasp waypoint computed from the detected cup center.
- `--cup-tag-id`, `--cup-tag-size`, and `--tag-to-cup-center-offset X Y Z` describe the cup-mounted tag.
- `--allow-config-cup-position-fallback` uses `--cup-position` if tag detection fails; without it, missing cup-tag detection is an error.

## Troubleshooting

If `mujoco` cannot be imported, make sure the `whisk-agent` environment is active:

```bash
conda activate whisk-agent
python -m pip show mujoco
```

If `lerobot` cannot be imported, install the kinematics extra:

```bash
python -m pip install "lerobot[kinematics]"
```

If AprilTag detection cannot be imported, install the detector dependency:

```bash
python -m pip install pupil-apriltags
```

If the viewer fails on macOS, use `mjpython` instead of `python`:

```bash
mjpython mujoco_sim/run_mujoco_simulation.py
```

If MuJoCo cannot find meshes, confirm that `scene.xml`, `scene_cup.xml`, `so101.xml`, and the `assets/` folder are all inside `simulation_code/model/`.
